# IOCP output and startup lookup measurements

2026-10-21, Windows Release x64. This is a follow-up experiment, separate from the original game development.

Baseline: 9e9110727ff5fa8c4cd016f9a55efe4aa93ecc4e, bounded queue with one blocking writer per connection.
Candidate: 8a6245d1a58fdbed77fc62b48eb6984a3af7f017, one shared IOCP output worker plus startup attack-table cache.

18 MOVE runs: 8/32/64 clients, 4 per room, 20 Hz/client, 2 s warmup, 10 s observation, 2 s drain, 3 repetitions per variant. Order alternates. The cache is not used by MOVE. All 187,200 expected in-room deliveries arrived in each variant across its nine runs, with zero cross-room deliveries, duplicates or malformed frames. Check results.json for exact per-run counts.

12 pressure runs: 8 clients, two rooms, 3 repeats of quiet and stopped-reader conditions for both variants. A client in room A stops reading. Probes originate and terminate inside healthy room B. These are not messages leaked from A to B. Both queue designs preserve 300/300 expected B-room deliveries in every run. Transport counters include in-flight bytes in the queue limit.

10 lookup runs: same actual UserManager code compiled with a replacement main, 100,000 cyclic lookups of seven entries, five alternating repetitions. Warm filesystem cache, startup loading excluded. Checksum 1,299,995 in every run. This microbenchmark does not measure game latency, FPS, or network throughput. Candidate file changes become visible only after a server restart. Harness and compiled-source/binary hashes are included.

Latency spans sender pre-write through observer newline receipt, including load-generator scheduling. CPU 100% means one logical core. No Unity rendering, WAN, database, or complete battle simulation. Three repetitions cannot establish statistical significance. Read all run values, including slower p95 medians.

The original baseline build manifest captured HEAD before an uncommitted lobby-snapshot correction was committed. source-verification.json verifies every pre-adaptation source hash against 9e9110; it does not silently rewrite the original manifest. Only loopback binding and test port are adapted for socket tests. Lookup main is replaced separately and recorded.

Raw latency CSVs are losslessly gzipped. Telemetry and transport counters are retained. Generated account fixtures and verbose server logs are omitted; fixtures can be regenerated by the harness. sha256.json hashes all archived files except itself.
